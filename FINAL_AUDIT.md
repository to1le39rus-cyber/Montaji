# МОНТАЖИ АА — production audit / 19.08.2026

## Итог

Production runtime приведён к одной понятной линии. Рабочая база не мигрировалась и не очищалась.

## Архитектура

- Cloud Firestore `appData/shared` остаётся источником истины.
- `appData/notes` изолирован от shared-данных.
- `app.js` — единственный production JavaScript runtime.
- `index.html` подключает только один module script.
- localStorage/sessionStorage не используются как рабочая база.
- чтение стартует через `getDocFromServer`;
- realtime — `onSnapshot`;
- записи — `runTransaction`.

- чистыми за сегодня;
- доход;
- расход;
- загрузка монтажей;
- умные сигналы;
- сегодняшние выезды;
- расходы сегодня;

## Замеры

Замер отделён от обычного монтажа:

- свободное время;
- отдельная стоимость;
- платный/бесплатный;
- факт оплаты;
- сохранение истории;
- `Замер → Монтаж`;
- связь между исходным замером и монтажом;
- возможность зачёта стоимости замера.

## Финансы

- выполненная работа считается доходом;
- долг не вычитает доход;
- расходы независимы;
- чистыми = доход − расходы;
- долги открываются кликом;
- расходы можно архивировать без физического удаления.

## История

Календарь работает как история рабочего дня, а не только как планировщик. Прошлая дата показывает выезды, доход, расходы, чистыми и долги.

Отмена выезда переводит его в `Отменён`, поэтому история не уничтожается.

## Mobile / Safari UX

- `viewport-fit=cover`;
- safe-area для нижней навигации и модалок;
- `overflow-x:hidden`;
- фиксированная ширина sheet;
- вертикальный scroll только внутри sheet;
- единая дизайн-система вместо нескольких UI-слоёв;
- светлая и тёмная темы.

## Security

Firestore Rules требуют подтверждённый email и запрещают anonymous access. Правила применяются и к `appData/notes`.

## Тестирование

Regression contract проверяет:

1. единственный runtime;
2. сохранение Firestore-контракта;
3. отсутствие local/session storage;
4. отдельный notes document;
5. flow замера;
6. финансовую семантику;
7. сохранение истории;
8. безопасные расходы;
9. mobile overflow/safe-area;
10. security rules;
11. новые быстрые действия.

Локально проверено:

```bash
node --check app.js
node --test tests/final-architecture.test.mjs
```

Оба прохода проходят.

GitHub Actions в текущем окружении завершается до выполнения шагов runner'а, поэтому его failure нельзя считать доказательством ошибки приложения. До live-release всё равно необходимы реальные Safari/Chrome + Firebase проверки на двух телефонах.
