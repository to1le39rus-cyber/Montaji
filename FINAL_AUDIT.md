# МОНТАЖИ АА — production audit / 19.08.2026

## Текущий результат

Production база успешно загружается в новую версию приложения. Существующие данные Firestore не мигрировались и не очищались.

## Архитектура

- Cloud Firestore `appData/shared` — source of truth.
- `appData/notes` изолирован от shared-данных.
- realtime — `onSnapshot`.
- записи — `runTransaction`.
- `localStorage/sessionStorage` не используются как рабочая БД.
- shared database загружается независимо от notes.
- при сетевой ошибке приложение не выдаёт пустую базу за актуальную.
- Anonymous Auth используется как прозрачный транспорт авторизации для двух рабочих устройств.

## Важный runtime debt

Текущая production-линия содержит `boot.js`, который временно накладывает совместимые runtime-патчи на существующий `app.js`.

Это сознательный стабилизационный слой после восстановления production базы. Следующий архитектурный шаг — перенести подтверждённые патчи непосредственно в `app.js` и удалить runtime patching. До этого момента новые патчи добавляются только через проверяемые инварианты.

## Capacity invariant

Дневная ёмкость — 3 монтажных окна.

Счётчик, календарь и проверка слота используют одно правило: выполненный монтаж всё ещё занимает своё окно в истории рабочего дня. Это устраняет состояние `3 выполненных / 0 из 3`.

## Замеры

- отдельный тип;
- свободное время;
- стоимость;
- оплата;
- зачёт в монтаж;
- связь `Замер → Монтаж`.

Форма содержит отдельное поле `measureCredit`, необходимое для конвертации.

## Финансы

- выполненная работа считается доходом;
- долг не вычитает доход;
- расходы независимы;
- чистыми = доход − расходы;
- история сохраняется;
- архив расходов не уничтожает исходную запись.

## Security note

Anonymous Auth + правило `request.auth != null` подходит для закрытого рабочего прототипа, но не является достаточной защитой для публичного масштабирования. Перед внешним доступом необходимо усилить контур App Check/ограниченными ролями или перейти на контролируемую аутентификацию.

## Release gate

Vercel deployment должен быть зелёным.

После стабилизации кода обязательна ручная проверка на Safari и Chrome:

- открыть существующий монтаж;
- создать;
- изменить;
- выполнить;
- создать долг;
- оплатить долг;
- создать замер;
- перенести замер в монтаж;
- добавить расход;
- открыть календарь;
- открыть деньги;
- проверить заметки;
- проверить второй телефон.
