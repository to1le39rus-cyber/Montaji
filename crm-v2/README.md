# CRM v2 — фундамент (ветка crm-v2-foundation)

Эта ветка **не трогает** ни `Astera-smart` (production), ни `notes-v3-sandbox-20260825`.
Ничего здесь пока не подключено к реальному приложению — это фундамент, который будет
интегрирован постепенно, шагами, с проверкой на каждом шаге.

## Статус: Шаг 1 из плана (docs/06-EXECUTION-PLAN.md)

Готово:
- `SCHEMA.md` — целевая схема данных (коллекции `jobs`, `notes`, `users`, `stores`,
  `publicSlots`, `bookingRequests`)
- `firestore.rules.v2` — ролевые правила безопасности (installer / manager / store)
- `migrate-jobs.mjs` — скрипт переноса текущих данных, с `--dry-run` по умолчанию
- `notes-v3.js` — единый модуль заметок (личные / публичные / срочные)
- `docs/` — полный пакет технической документации (архитектура, дизайн, QA, бизнес-логика,
  бэклог будущих функций, пошаговый план)

## Важно: режим работы без Firebase Blaze

Проект сейчас на бесплатном тарифе (Spark) — Cloud Functions недоступны физически. Поэтому
`firestore.rules.v2` временно разрешает команде (`installer`/`manager`) писать в `publicSlots`
напрямую, а подтверждение заявок от магазинов (`bookingRequests`) делается вручную человеком,
а не автоматикой. Это осознанное и безопасное решение для текущего этапа — race condition при
бронировании исключается тем, что запись в `jobs` всегда делает человек с ролью team, а не
клиентский код магазина напрямую.

Когда будет подключён Blaze — путь миграции на Cloud Functions уже описан в
`docs/02-TECH-ARCHITECTURE.md`, ничего не придётся переделывать с нуля, только заменить способ
записи `publicSlots` и добавить автоматическое подтверждение при желании.

## Шаг 3 (готово): миграция данных выполнена

Запущено через Cloud Shell. Результат: перенесено 44/44 монтажей, 36/36 расходов, контроль
суммы `price` сошёлся 1:1 (439050 = 439050). Коллекции `jobs/{id}` и `expenses/{id}` в Firestore
теперь содержат реальные данные. `appData/shared` не изменён — остаётся как резервная копия.

## Шаг 4 (в процессе): адаптер данных

`data-adapter-v2.js` — замена всего трёх функций из `app.js` (`loadServer`, `startRealtime`,
`saveShared`) под работу с коллекциями `jobs`/`expenses` вместо одного документа
`appData/shared`. Остальные 60+ функций в `app.js` (рендер карточек, расчёт долгов/дохода,
слоты, экраны) **не переписываются** — они уже работают через `saveShared(mutator)` как единую
точку записи, поэтому продолжают работать без изменений поверх нового адаптера. Подробное
обоснование — в комментарии в начале файла.

Ещё не подключено к `index.html`/`app.js` — ждёт миграции данных (см. ниже).

## Ничего не задеплоено

Эти файлы физически не подключены ни к `index.html`, ни к `firestore.rules` (тому, что реально
применяется в проекте) — они лежат рядом для ревью. Ни к продакшену, ни к текущему sandbox это
изменений не вносит.
