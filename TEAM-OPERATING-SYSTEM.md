# МОНТАЖИ АА — команда уровня production

Дата: 20.08.2026

Этот файл — operating system проекта: каждый релиз проходит через несколько независимых профессиональных взглядов.

## 1. Командир корабля / Product Owner

Держит единую цель приложения и не позволяет фичам разрушать рабочий сценарий монтажника.

Правило: сначала надёжность ежедневной работы, потом красота, потом новые функции.

## 2. Chief Product Strategist

Превращает реальные процессы в понятную систему: график → выезд → выполнение → деньги → история.

Проверяет каждую новую функцию:
- зачем она монтажнику;
- экономит ли она время;
- не создаёт ли новый путь ошибок;
- что произойдёт с существующими данными.

## 3. Principal Software Architect

Отвечает за единый source of truth и отсутствие скрытых источников данных.

Контракт проекта:
- Firestore `appData/shared` — source of truth;
- `appData/notes` — отдельный bounded data set;
- записи через `runTransaction`;
- realtime через `onSnapshot`;
- никаких `localStorage/sessionStorage` как рабочей БД;
- ошибка notes не должна делать shared недоступным;
- ошибка сети не должна маскироваться под пустую актуальную базу.

## 4. Principal Frontend Engineer / Code Quality

Проверяет читаемость и предсказуемость JavaScript.

Красные флаги:
- runtime patching ради постоянной бизнес-логики;
- дублирование функций;
- мёртвые UI-слои;
- обращения к отсутствующим DOM-элементам;
- silent catch;
- destructive update без подтверждения;
- бизнес-правила в случайных обработчиках.

`boot.js` допускает только явно ограниченный compatibility-loader до момента переноса всех его замен в канонический `app.js`; каждая такая замена обязана иметь regression test.

## 5. Staff UX / Interaction Designer

Приложение должно быть быстрее телефона, а не сложнее телефона.

Контроль: одна главная задача на экран, важное видно сразу, большие touch targets, минимум текста, быстрые действия в карточке, понятные loading/success/error states.

## 6. Visual Director

Контролирует типографику, ритм, контраст, CTA, светлую/тёмную тему, safe-area iPhone Safari и отсутствие визуального шума.

## 7. QA Lead / Test Engineering

Тестирует четыре слоя:
1. happy path;
2. invalid input;
3. network/database failure;
4. повторное действие и конфликт двух телефонов.

Функция считается готовой только после проверки сохранения после перезагрузки и realtime на втором клиенте.

## 8. Security Engineer

Проверяет Firebase Auth, Firestore Rules, отсутствие серверных секретов в клиентском коде и безопасное поведение backup/restore.

## 9. Technical Writer / README Editor

README должен позволять новому разработчику понять запуск, Firebase, deploy, тесты и production gate без археологии коммитов.

## 10. Release Manager

Перед production:
- regression tests зелёные;
- Firebase Hosting deployment зелёный;
- нет временного repair workflow или незакоммиченных файлов;
- бизнес-инварианты отражены в документации;
- live smoke-test выполнен на Safari и Chrome.

## Главный принцип

**Мы не чиним симптом. Мы ищем нарушенный контракт, исправляем источник и добавляем тест, который не позволит проблеме вернуться.**
