# МОНТАЖИ АА — команда уровня production

Дата: 19.08.2026

Этот файл — не декоративный список ролей. Это operating system проекта: каждый релиз проходит через несколько независимых профессиональных взглядов.

## 1. Командир корабля / Product Owner

**Задача:** держать единую цель приложения и не позволять фичам разрушать рабочий сценарий монтажника.

Правило: сначала надёжность ежедневной работы, потом красота, потом новые функции.

## 2. Chief Product Strategist

**Задача:** превращать реальные процессы в понятную систему: график → выезд → выполнение → деньги → история.

Проверяет каждую новую функцию вопросами:
- зачем она монтажнику;
- экономит ли она время;
- не создаёт ли новый путь ошибок;
- что произойдёт с существующими данными.

## 3. Principal Software Architect

**Задача:** архитектура без скрытых зависимостей, двойных источников истины и временных костылей.

Контракт проекта:
- Firestore `appData/shared` — source of truth;
- `appData/notes` — отдельный bounded data set;
- транзакционные записи через `runTransaction`;
- realtime через `onSnapshot`;
- никаких `localStorage/sessionStorage` как рабочей БД;
- никакой логики, которая молча заменяет серверные данные пустым состоянием при частичной ошибке.

## 4. Principal Frontend Engineer / Code Quality

**Задача:** простой, читаемый и предсказуемый JavaScript.

Красные флаги:
- runtime patching ради постоянной логики;
- дублирование функций;
- мёртвые UI-слои;
- обращения к DOM-элементам, которых нет в HTML;
- silent catch;
- destructive update без подтверждения;
- бизнес-правила, спрятанные в случайном обработчике кнопки.

## 5. Staff UX / Interaction Designer

**Задача:** приложение должно быть быстрее телефона, а не сложнее телефона.

Принципы:
- одна главная задача на экран;
- важное видно до первого скролла;
- большие touch targets;
- минимум текста в рабочем состоянии;
- быстрые действия прямо в карточке;
- опасные действия отделены визуально;
- состояния loading / success / error всегда различимы.

## 6. Visual Director

**Задача:** цельная дизайн-система, а не набор красивых блоков.

Контроль:
- типографическая иерархия;
- ритм отступов;
- контраст;
- визуальный вес CTA;
- светлая/тёмная тема;
- iPhone Safari safe-area;
- отсутствие визуального шума.

## 7. QA Lead / Test Engineering

**Задача:** искать не только баги, но и неправильные сценарии.

Тестирует четыре слоя:
1. happy path;
2. invalid input;
3. network/database failure;
4. повторное действие и конфликт двух телефонов.

Особое правило: функция считается готовой только после проверки сохранения данных после перезагрузки и realtime на втором клиенте.

## 8. Security Engineer

**Задача:** база не должна становиться доступной случайному клиенту только ради удобства разработки.

Проверяет Firebase Auth, Firestore Rules, отсутствие секретов в клиентском коде и безопасное поведение backup/restore.

## 9. Technical Writer / README Editor

**Задача:** любой человек должен понять проект без археологии коммитов.

README описывает запуск, Firebase, deploy, тесты и production gate.

## 10. Release Manager

Перед production:
- код проходит статические regression tests;
- Vercel build/deploy зелёный;
- нет незакоммиченных временных файлов;
- изменённые бизнес-правила отражены в документации;
- live smoke-test выполнен на Safari и Chrome.

## Главный принцип

**Мы не чинim симптом. Мы ищем контракт, который нарушен, исправляем источник и добавляем тест, который не позволит проблеме вернуться.**
