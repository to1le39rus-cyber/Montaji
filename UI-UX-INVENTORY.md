# МОНТАЖИ АА — UI/UX INVENTORY

> **Канонический инвентарь интерфейса.**
> Этот документ фиксирует, какие экраны, окна, sheets, модальные состояния и системные поверхности существуют в приложении, прежде чем мы начнём делать единый визуальный язык.
>
> Цель: не допустить ситуации «на одном экране модалка одна, на другом такая же, но другая». Все новые UI-поверхности должны либо использовать существующий паттерн, либо сначала быть добавлены сюда.
>
> **Визуальная реализация регулируется `UI-UX-SYSTEM.md`.**

## 1. Принцип продукта

«Монтажи АА» — рабочее приложение. Оно должно быть одновременно очень красивым, быстрым, лёгким, очевидным, приятным и живым. Красота должна усиливать скорость, уверенность и удовольствие от работы.

### Wow-принцип

Анимация используется как микровзаимодействие: плавное открытие, приятный tap feedback, короткий success, мягкое изменение статуса/цифр, живые переходы. Не допускаются тяжёлый blur везде, бесконечные параллаксы, постоянные observers/timers ради анимации и эффекты, заметно бьющие по iPhone/Safari.

## 2. Каноническая навигация

| ID | Экран | Назначение | Приоритет |
|---|---|---|---|
| `todayScreen` | **Сегодня** | Что происходит сейчас и ближайшие действия | P0 |
| `scheduleScreen` | **График** | Планирование по дням и нагрузка | P0 |
| `moneyScreen` | **Деньги** | Доходы, расходы, долги и источники | P0 |
| `clientsScreen` | **Клиенты** | Быстрый доступ к базе клиентов | P1 |
| `moreScreen` | **Ещё** | Система, экспорт, backup, аккаунт | P1 |

Нижняя навигация — единый глобальный компонент.

### Глобальные поверхности

1. Top bar — бренд, дата, sync state.
2. Bottom navigation — 5 разделов.
3. FAB «＋» — глобальное добавление.
4. Toast — короткая обратная связь.
5. Modal / Bottom Sheet — единый контекстный shell.
6. Backdrop + handle + close — единый механизм sheet.

## 3. Auth Screen

Не входит в основную навигацию. Содержит бренд, Email, Пароль, Войти, Регистрация, Забыли пароль?, сообщения состояния.

Состояния: initial, input, signing in, invalid credentials/email, disabled account, too many attempts, offline, registration, confirmation sent, reset sent, Firebase unavailable.

## 4. Сегодня

Главная задача: за несколько секунд понять, что происходит сегодня.

Вопросы пользователя:

1. Что у меня сегодня?
2. Сколько монтажей?
3. Что с деньгами?
4. Есть ли проблема/долг?
5. Что дальше?

Зоны: hero нагрузки/результата, доход/расход, индикатор нагрузки, неделя/месяц, «Что важно», список выездов, расходы сегодня, ближайшие дни, заметки и архив заметок.

Основной компонент — Job Card Today / primary. Карточка лёгкая и сканируемая; операционные действия находятся в деталях/Day Sheet.

## 5. График

Содержит месяц, навигацию по месяцам, календарную сетку, легенду, состояние дня, фактическое количество монтажей, индикатор замера.

Tap по дню открывает Day Sheet.

**Три монтажных окна — плановые пресеты, не лимит. 4/5/6+ монтажей допустимы. UI не показывает 3/3 как потолок.**

## 6. Day Sheet — рабочий день

Тип: Bottom Sheet / Modal.

Содержит дату, монтажей, плановую среднюю, свободные плановые окна, `＋ Выезд`, `− Расход`, `＋ Заметка`, Плановые окна, Дополнительные монтажи, Другие выезды, Историю выполненных, banner долга при наличии и `Открыть полный день →`.

Day Sheet — рабочая поверхность. Здесь допустимы операционные действия.

## 7. Day Archive / Полный день

Тип: Bottom Sheet / Modal.

История выбранного дня + деньги: дата, доход, расход, чистый результат, выезды, расходы, редактирование расхода, `＋ Расход за дату`.

Это контекстное окно, не отдельный раздел навигации.

## 8. Canonical Job Card

Одна сущность — одна базовая карточка. Варианты плотности: Today / primary, Day Sheet / compact, History / compact, Client context, Detail.

Информация: клиент, время/слот, тип, магазин/источник, сумма, адрес, комментарий, статус, дата выполнения, долг, зачёт замера.

**Комментарий к монтажу — рабочая информация.** В компактной карточке используется аккуратный раскрываемый preview.

Нельзя создавать новый визуальный тип карточки только из-за другого экрана.

## 9. Job Detail — Подробнее

Тип: Bottom Sheet / Modal, read-only по умолчанию.

Содержит клиента, тип/время/источник, статус, сумму, адрес, телефон, комментарий, Яндекс, 2ГИС, Позвонить, Отправить адрес, при возможности `✓ Выполнено`, `Изменить данные`.

**Подробнее ≠ Редактировать.**

## 10. Job Edit — Новый выезд / Изменить выезд

`jobModal`, единый form bottom sheet.

Типы записи: Монтаж, Замер, Рекламация, Доставка, Сервис, Доход.

Базовые поля: дата, плановый слот/свободное время, клиент/за что, телефон, сумма, адрес, источник/магазин, статус, дата выполнения, оплата, комментарий.

Для замера: стоимость, оплачен, зачёт в монтаж, перенос в монтаж.

Действия: Сохранить, Перенести в монтаж в соответствующем состоянии, В архив; для тестовой записи — безопасное удаление теста.

**Форма одна. Меняется контент, а не shell.**

## 11. Expense

Текущее состояние: `app.js` содержит `openExpense()` и ожидает `#expenseModal`, `#expenseForm`, `#expenseId`, `#expenseDate`, `#expenseAmount`, `#expenseCategory`, `#expenseComment`, но canonical `index.html` сейчас не содержит этой модалки.

**Статус: GAP / отдельная реализация.**

Планируемый Expense Sheet: дата, сумма, категория, комментарий, сохранить, закрыть и корректное действие редактирования/архивации по бизнес-правилам. Использует общий shell.

## 12. Note

Текущее состояние: `app.js` содержит `openNote()` и ожидает `#noteModal`, `#noteForm`, `#noteText`, но canonical `index.html` сейчас не содержит этой модалки.

**Статус: GAP / отдельная реализация.**

Планируемый Note Sheet: короткий текст, сохранить, закрыть. Архивирование остаётся частью существующей note-системы до отдельного бизнес-решения.

## 13. Другие UI surfaces

### Confirm

Единый паттерн подтверждения опасного действия: короткий заголовок, последствия, primary action, cancel.

### Action Sheet

Выбор одного действия из нескольких связанных вариантов.

### Toast

Короткий результат операции.

### Native file picker

Для backup/import, без фальшивого файлового браузера, если нативный picker решает задачу лучше.

## 14. Системные состояния

Минимальный набор: loading, empty, error, offline, saving, saved, conflict, permission denied, disabled, completed, cancelled.

Каждое состояние имеет единый визуальный язык.

## 15. Legacy boundary

`secure-app/` — исторический/legacy слой. Он не является источником истины для canonical runtime. Не переносить его UI автоматически в новый дизайн.

## 16. Правило расширения

Новая фича:

1. проверить существующий screen/component/sheet;
2. переиспользовать его, если подходит;
3. если не подходит — добавить новую сущность в inventory;
4. определить паттерн в `UI-UX-SYSTEM.md`;
5. только после этого реализовать UI.

**Никаких скрытых модалок, временных карточек и уникальных компонентов только для одного места.**
