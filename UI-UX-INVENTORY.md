# МОНТАЖИ АА — UI/UX INVENTORY

> **Канонический инвентарь интерфейса.** Фиксирует все известные экраны, окна, sheets, модальные и системные поверхности до визуального редизайна.
>
> Цель: не допустить ситуации «на одном экране модалка одна, на другом такая же, но другая». Все новые UI-поверхности используют существующий паттерн либо сначала добавляются сюда.
>
> Визуальная реализация регулируется `UI-UX-SYSTEM.md`.

## Основная навигация

| ID | Экран | Назначение | Приоритет |
|---|---|---|---|
| `todayScreen` | **Сегодня** | Текущий день и ближайшие действия | P0 |
| `scheduleScreen` | **График** | Планирование и нагрузка | P0 |
| `moneyScreen` | **Деньги** | Доходы, расходы, долги, источники | P0 |
| `clientsScreen` | **Клиенты** | База клиентов | P1 |
| `moreScreen` | **Ещё** | Система, backup, экспорт, аккаунт | P1 |

## Auth Screen

Отдельный входной экран: бренд, Email, Пароль, Войти, Регистрация, Забыли пароль?, сообщения состояния.

Состояния: initial, input, signing in, invalid credentials/email, disabled account, too many attempts, offline, registration, confirmation sent, reset sent, Firebase unavailable.

## Сегодня

Зоны: hero нагрузки/результата, доход/расход, индикатор нагрузки, неделя/месяц, «Что важно», список выездов, расходы сегодня, ближайшие дни, заметки и архив заметок.

Основной компонент — Job Card Today / primary. Карточка лёгкая и сканируемая; операционные действия находятся в Подробнее/Day Sheet.

## График

Месяц, навигация, календарная сетка, легенда, состояние дня, фактическое количество монтажей, индикатор замера.

Tap по дню открывает Day Sheet.

**Три монтажных окна — плановые пресеты, не лимит. 4/5/6+ монтажей допустимы. `3/3` не является потолком.**

## Day Sheet — рабочий день

Bottom Sheet / Modal. Содержит дату, монтажей, плановую среднюю, свободные плановые окна, `＋ Выезд`, `− Расход`, `＋ Заметка`, Плановые окна, Дополнительные монтажи, Другие выезды, Историю выполненных, banner долга и `Открыть полный день →`.

## Day Archive / Полный день

Bottom Sheet / Modal. Дата, доход, расход, чистый результат, выезды, расходы, редактирование расхода, `＋ Расход за дату`.

Контекстное окно выбранного дня, не отдельный раздел навигации.

## Canonical Job Card

Одна сущность — одна базовая карточка. Варианты: Today / primary, Day Sheet / compact, History / compact, Client context, Detail.

Данные: клиент, время/слот, тип, магазин/источник, сумма, адрес, комментарий, статус, дата выполнения, долг, зачёт замера.

**Комментарий к монтажу — рабочая информация.** Компактный вариант использует аккуратный раскрываемый preview.

## Job Detail — Подробнее

Bottom Sheet / Modal, read-only по умолчанию. Клиент, тип/время/источник, статус, сумма, адрес, телефон, комментарий, Яндекс, 2ГИС, Позвонить, Отправить адрес, при возможности `✓ Выполнено`, `Изменить данные`.

**Подробнее ≠ Редактировать.**

## Job Edit — Новый выезд / Изменить выезд

`jobModal`, единый form bottom sheet. Типы: Монтаж, Замер, Рекламация, Доставка, Сервис, Доход.

Поля: дата, плановый слот/свободное время, клиент/за что, телефон, сумма, адрес, источник/магазин, статус, дата выполнения, оплата, комментарий. Для замера: стоимость, оплачен, зачёт в монтаж, перенос в монтаж.

Действия: Сохранить, Перенести в монтаж в соответствующем состоянии, В архив; тестовая запись может иметь безопасное удаление теста.

**Форма одна. Меняется контент, а не shell.**

## Expense

Текущее состояние: `app.js` содержит `openExpense()` и ожидает `#expenseModal`, `#expenseForm`, `#expenseId`, `#expenseDate`, `#expenseAmount`, `#expenseCategory`, `#expenseComment`, но canonical `index.html` сейчас не содержит этой модалки.

**Статус: GAP / отдельная реализация.** Планируемый Expense Sheet: дата, сумма, категория, комментарий, сохранить, закрыть и корректное редактирование/архивация по бизнес-правилам.

## Note

Текущее состояние: `app.js` содержит `openNote()` и ожидает `#noteModal`, `#noteForm`, `#noteText`, но canonical `index.html` сейчас не содержит этой модалки.

**Статус: GAP / отдельная реализация.** Планируемый Note Sheet: короткий текст, сохранить, закрыть.

## Другие поверхности

- **Confirm** — короткий заголовок, последствия, primary action, cancel.
- **Action Sheet** — выбор одного действия из связанных вариантов.
- **Toast** — короткий результат операции.
- **Native file picker** — backup/import, если нативный picker решает задачу лучше.

## Системные состояния

Минимальный набор: loading, empty, error, offline, saving, saved, conflict, permission denied, disabled, completed, cancelled.

## Legacy boundary

`secure-app/` — исторический/legacy слой. Не является источником истины для canonical runtime и не должен автоматически диктовать новый дизайн.

## Правило расширения

Новая фича: проверить существующий screen/component/sheet → переиспользовать → если не подходит, добавить сущность в inventory → определить паттерн в `UI-UX-SYSTEM.md` → только потом реализовать UI.

**Никаких скрытых модалок, временных карточек и уникальных компонентов только для одного места.**
