# Монтажи АА — production

Мобильное PWA для ежедневной работы монтажника: график, замеры, клиенты, деньги, расходы, долги, заметки и история рабочего дня.

## Production-контур

- Каноническая production-ветка: `Astera-smart`.
- Firebase project: `montaj-39`.
- Firebase Hosting: `https://montaj-39.web.app/`.
- Cloud Firestore — единственный источник актуальных рабочих данных.

Исторические ветки используются только для rollback/reference. Новые параллельные runtime-версии не создаём.

## Архитектура

- `app.js` — единственный рабочий JavaScript runtime.
- `index.html` — единственная production-точка входа.
- `styles.css` — единая дизайн-система и mobile UX.
- `firebase-config.js` — конфигурация Firebase.
- `firestore.rules` — доступ только подтверждённым email/password пользователям.
- `appData/shared` — существующая рабочая база монтажей и расходов.
- `appData/notes` — отдельный документ общих заметок, чтобы старые записи shared не могли их затереть.
- Firestore `onSnapshot` — realtime.
- Firestore transaction — конкурентная запись.
- `localStorage`/`sessionStorage` не используются как рабочая база.

## Бизнес-логика

### Монтаж

Выполненный монтаж учитывается по фактической дате выполнения. Оплата хранится отдельно:

- выполнено + оплачено;
- выполнено + не оплачено = долг.

Долг не уменьшает доход: работа уже выполнена. Он отображается отдельным показателем и открывается кликом прямо в карточку монтажа.

### Замер

Замер — отдельный тип выезда. Для него нет обязательной суммы монтажа и нет искусственного ограничения стандартным монтажным слотом.

Можно указать:

- произвольное время;
- клиента;
- телефон;
- адрес;
- источник;
- платность;
- стоимость замера;
- факт оплаты;
- комментарий.

После замера есть flow `Перенести в монтаж`. Исходный замер сохраняется, а новый монтаж хранит связь с ним. Платный замер может быть указан как зачёт в стоимости последующего монтажа без уничтожения истории.

### Расходы

Расходы независимы от монтажей: топливо, парковка, материалы, инструмент, аренда и т.д. Их можно исправлять или отправлять в архив без физического уничтожения истории.

### История дня

Календарь показывает не только будущий график. Любая прошедшая дата открывается как полноценный рабочий день:

- выезды;
- выполненные работы;
- доход;
- расходы;
- чистый результат;
- долги;
- заметки.

## UX-функции

- быстрый `+` с типизированным меню;
- быстрые действия `В пути`, `Выполнено`, `Оплачено`;
- Яндекс Карты и 2ГИС;
- звонок клиенту;
- отправка адреса через системный Share API или копирование;
- общие заметки + архив;
- светлая и тёмная тема;
- mobile-first safe-area;
- защита от горизонтального overflow;
- server-first поведение при отсутствии сети: старые данные не выдаются за актуальные.

## CI/CD

`.github/workflows/validate.yml` проверяет syntax, regression contract, production wiring, карты, security rules и отсутствие legacy runtime.

`.github/workflows/deploy.yml` — единственный production deploy в Firebase Hosting и запускается из `Astera-smart`.

Перед release обязательно:

```bash
node --check app.js
node --test tests/final-architecture.test.mjs
```

## Правило данных

Никаких destructive migration без отдельного подтверждения владельца. Никакого создания новой Firebase project, нового `appData` или альтернативной рабочей базы.

**Сначала сохранить. Потом проверить. Потом изменить. Потом снова проверить. Только потом выкатывать.**
