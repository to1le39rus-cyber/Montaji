# Монтажи АА — production

Мобильное PWA для графика монтажей, клиентов, доходов, расходов и архива.

## Production-контур

Каноническая версия: `v5-final`.

`Astera-smart` синхронизирован с тем же production-коммитом, чтобы старые ссылки на рабочую ветку не уводили в другую версию. Новые параллельные версии приложения не создаём.

## Главный принцип

**Cloud Firestore — единственный источник правды.**

Приложение не хранит рабочую базу в `localStorage` и не работает по схеме local-first. Если интернет/Firestore недоступен, старая информация не показывается и новые изменения не принимаются.

## Общая работа

Два телефона входят через Firebase Authentication по подтверждённому email/password и подключаются к одному документу `appData/shared`.

- realtime обновления через Firestore `onSnapshot`;
- конкурентные изменения через Firestore transaction;
- отменённые записи сохраняются в истории;
- выполненные работы учитываются по фактической дате;
- доход считается только по выполненным работам и дополнительному доходу, который создаётся как выполненный;
- расходы считаются независимо от доходов;
- JSON — резервный экспорт, не источник текущих данных.

## Деньги

Главный экран показывает фактический доход за день и чистыми после расходов. Экран «Деньги» даёт переключение День / Неделя / Месяц / Всё и отдельно показывает доход, расходы, чистый результат и долги.

## Production-файлы

- `index.html` — интерфейс;
- `app.js` — единственная рабочая логика;
- `firebase-config.js` — конфигурация Firebase;
- `firestore.rules` — доступ к базе;
- `styles.css` — UI;
- `firebase.json` — Firebase Hosting deployment;
- `.github/workflows/validate.yml` — CI проверки;
- `.github/workflows/deploy.yml` — единственный production deploy в Firebase Hosting;
- `MONTAZHI-AA-OPERATING.md` — правила дальнейшей работы.

Не создавать новые `app-vN.js`, `sync-vN`, отдельные базы или новые production-контуры. Любые следующие изменения делаются в текущем production-коде после проверки.
