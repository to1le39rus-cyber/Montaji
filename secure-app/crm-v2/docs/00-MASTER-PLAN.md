# 00 — МАСТЕР-ПЛАН. Как пользоваться этим пакетом документов

Этот пакет — техническое задание полного цикла для превращения "Монтажи АА" в CRM с ролями
(монтажник / менеджер / магазин). Написан так, чтобы его можно было скормить любой нейронке
(включая будущие сессии Claude, Claude Code, или другого агента) **по одному документу за раз**,
без необходимости заново объяснять контекст с нуля.

## Состав пакета

| Файл | Роль-автор | Что внутри |
|---|---|---|
| `01-BUSINESS-LOGIC.md` | Бизнес-аналитик / стратег | Инварианты, роли, сценарии, что нельзя нарушать |
| `02-TECH-ARCHITECTURE.md` | Архитектор / программист | Стек, структура данных, безопасность, миграция |
| `03-DESIGN-SYSTEM.md` | Дизайнер | Токены, компоненты, экраны по ролям, принципы UX |
| `04-QA-TEST-PLAN.md` | Тестировщик | Матрица тестов, acceptance criteria, регрессия |
| `05-FUTURE-FEATURES.md` | Продуктовый стратег | Функции на будущее, которые вы могли не предусмотреть |
| `06-EXECUTION-PLAN.md` | PM / технический директор | Пошаговый план для ИИ-агента — что делать в каком порядке |

## Как использовать с ИИ-агентом (Claude Code и т.п.)

1. Каждый шаг из `06-EXECUTION-PLAN.md` — самодостаточная задача. Агенту скармливается:
   - сам шаг из `06-EXECUTION-PLAN.md`,
   - плюс тот раздел `02-TECH-ARCHITECTURE.md` / `03-DESIGN-SYSTEM.md`, на который шаг ссылается.
2. Агент не должен видеть весь пакет целиком сразу — это тратит контекст впустую. Подавать по частям.
3. После каждого шага — обязательная сверка с `04-QA-TEST-PLAN.md` (соответствующий блок) перед
   переходом к следующему шагу. Это защищает от повторения истории "патч → READY → снова не
   работает", описанной в исходном аудите проекта.
4. `01-BUSINESS-LOGIC.md` — источник истины при любом конфликте трактовок. Если агент предлагает
   решение, нарушающее инвариант оттуда — решение неверное, независимо от того, насколько красиво
   оно реализовано технически.

## Порядок работы (кратко, подробности — в 06)

```
Спринт 0: стабилизация текущего sandbox (уже описан в отдельном аудите, предпосылка ко всему)
Спринт 1: схема данных + правила безопасности          (сделано — предыдущая передача)
Спринт 2: миграция + серверные функции (Cloud Functions)
Спринт 3: UI монтажник/менеджер поверх новой схемы
Спринт 4: заметки v3 (личные/публичные/срочные)
Спринт 5: push-уведомления
Спринт 6: портал магазина
Спринт 7: полировка дизайна, доступность, тестирование
Спринт 8+: функции из 05-FUTURE-FEATURES.md — по приоритету, который вы выберете
```
