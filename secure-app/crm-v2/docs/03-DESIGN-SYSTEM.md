# 03 — ДИЗАЙН-СИСТЕМА И UX

Роль-автор: дизайнер.

---

## 1. Что уже хорошо и трогать не нужно

Текущая визуальная база (`styles.css`) — тёмно-оливковая палитра, CSS-переменные, закруглённые
карточки, `backdrop-filter` — выглядит целостно и современно, это хорошая основа. Проблема не в
эстетике, а в том, что её переопределяют 3–4 конкурирующих CSS-файла (см. прошлый аудит). Задача
дизайн-этапа — не "придумать заново", а **консолидировать в одну систему токенов** и спроектировать
новые экраны в этой же логике.

## 2. Принцип для всех трёх ролей: одна кодовая база стилей, разные наборы экранов

Не отдельные "дизайны" для монтажника/менеджера/магазина — один визуальный язык, но:
- Монтажник/менеджер: полный набор экранов (как сейчас + заметки v3).
- Магазин: **сильно урезанный** интерфейс — 2 экрана: календарь + мои заявки. Не показывать
  нижнюю навигацию с 5 пунктами, если у роли есть только 2 раздела — это база хорошего мобильного
  UX (не показывать то, чем нельзя пользоваться).

## 3. Design tokens (свести все CSS-переменные в один источник)

```css
:root {
  --bg:#f4f3ef; --card:#fff; --ink:#111611; --muted:#7b817b;
  --line:rgba(20,30,22,.10); --olive:#68775b; --olive-dark:#263126;
  --soft:#e9eee6; --danger:#9a4035; --warning:#8d543d; --success:#58714e;
  --radius-lg:24px; --radius-md:17px; --radius-sm:11px;
  --nav-height:84px;
}
```

Новые токены для ролевой дифференциации (не меняя основную палитру — просто акцентный цвет
бейджа роли, чтобы монтажник на встрече с менеджером визуально понимал, что видит "менеджерский"
экран, если появятся отличия в действиях):

```css
--role-installer: var(--olive);
--role-manager: #4a5a8f;
--role-store: #8a6a3d;
```

## 4. Экраны — что добавляется к существующим пяти (Сегодня/График/Деньги/Клиенты/Ещё)

### Заметки (обновлённый экран, не отдельная вкладка — блок на "Сегодня" + отдельный полноэкранный список)
- Бейджи видимости прямо на карточке: 🔒 Личная / 👥 Общая / ⚠️ Срочно — задизайнено уже в
  `notes-v3.js` (`renderList`) как основа, дизайнеру — довести до финального визуала.
- Просроченные — визуально выделены (не только текстом "Просрочено", но и цветом левой границы
  карточки, по аналогии с `.job-measure{border-left:3px solid var(--olive)}` — переиспользовать
  паттерн, не изобретать новый).
- Модалка создания — тип видимости выбирается явно (сегмент-контрол: Личная / Общая / Срочно),
  при выборе "Срочно" — появляется мультиселект монтажников (или "Все").

### Экран магазина — "Календарь" (главный и единственный сложный экран роли store)
- Календарь как в текущем `#scheduleScreen`, но легенда упрощена до двух состояний: занято/свободно
  (не показывать типы работ — магазину это не нужно и не должно быть видно).
- Тап по свободной дате → шторка (`.sheet`, переиспользовать существующий компонент) с формой
  заявки: комментарий + кнопка "Отправить заявку".
- Отдельный маленький раздел "Мои заявки" — список со статусами (На рассмотрении/Подтверждено/
  Отклонено), без нижней навигации на 5 пунктов — просто переключатель "Календарь / Мои заявки"
  вверху экрана.

### Уведомления (новый паттерн, которого сейчас нет вообще)
- Badge-счётчик на иконке (сейчас есть только `themeBtn` в topbar — добавить рядом колокольчик
  с счётчиком непрочитанных срочных заметок/подтверждённых заявок).
- Тап → список последних событий → тап по событию → deep-link на карточку монтажа/заметки.

## 5. Мобильные принципы (закрепляем как чек-лист дизайн-ревью, не только для этого проекта)

- Минимальный размер тач-таргета — 44×44px (Apple HIG) — проверить кнопки `.mini-btn` в текущих
  заметках (`padding:5px 7px` — вероятно, меньше нормы, поправить в новой версии).
- `font-size` инпутов ≥16px (уже соблюдается — не регрессировать).
- Одна колонка на узких экранах для `.form-row` — уже есть в медиа-запросах, но см. прошлый
  аудит про каскадный конфликт — при консолидации CSS сохранить именно это правило.
- Не использовать `user-scalable=no` (было найдено как регрессия в sandbox — не переносить в
  новую версию).
- Пустые/загрузочные/ошибочные состояния — для каждого нового экрана (особенно "Мои заявки" у
  магазина: пусто / загрузка / нет связи) — не оставлять "белый экран" ни в одном случае,
  соответствует инварианту 17 исходного документа ("недоступность сети нельзя показывать как
  пустая база").

## 6. Тон и язык интерфейса

Короткие, разговорные, конкретные подписи (как уже сделано: "чистыми", "＋ Заметка") — не менять
на канцелярит при добавлении новых экранов. Для магазина — чуть более формальный, но не
"корпоративный" тон (это партнёр, не сотрудник, но и не случайный клиент): "Заявка отправлена",
"Ждём подтверждения от команды" — по аналогии с текущими toast-сообщениями.
