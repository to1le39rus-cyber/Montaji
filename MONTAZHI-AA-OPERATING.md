# МОНТАЖИ АА — рабочая инструкция

## 1. Единственный источник правды

- **Общая база:** Cloud Firestore `appData/shared`.
- **Клиентская база данных:** отсутствует.
- **localStorage для монтажей, расходов и архива:** не используется.
- **Интерфейс:** PWA «Монтажи АА».

Принцип: серверная база — единственная актуальная версия данных. Если интернет недоступен или Firestore не отвечает, приложение не показывает старую локальную копию и не принимает изменения.

## 2. Два телефона

Оба телефона входят под подтверждёнными Firebase email/password аккаунтами и подключаются к одному документу `appData/shared`.

Изменения приходят через Firestore realtime listener. Запись выполняется через Firestore transaction, поэтому два одновременных изменения не должны просто перезаписать друг друга последним запросом.

## 3. Что происходит без интернета

- На экране появляется `Нет интернета · данные не загружены`.
- Старые данные не подставляются из браузера.
- Сохранение, удаление и изменение блокируются до восстановления связи.
- После восстановления сети приложение снова получает данные с сервера.

## 4. Безопасность

Firestore Rules разрешают доступ только подтверждённым неанонимным пользователям Firebase Authentication.

Анонимная авторизация больше не используется как production-доступ.

## 5. Монтаж

`+` → тип → дата → слот → клиент → телефон → адрес → магазин → сумма → статус → комментарий → сохранить.

Слоты:
- 10:00–12:00
- 14:00–16:00
- 3-й слот / резерв

Одновременно в одном слоте нельзя иметь два активных выезда.

## 6. Выполнение

При статусе `Выполнен` можно указать фактическую дату выполнения. Финансовые показатели используют фактическую дату выполнения.

## 7. Перенос и отмена

Перенос сохраняется как изменение плановой даты/статуса.

Отменённая запись остаётся в истории, но не участвует в фактическом доходе.

## 8. Доходы и расходы

`+ Доход` — дополнительная платная работа.

`− Расход` — топливо, парковка, дорога и другие расходы дня.

Чистый результат = доход − расходы.

## 9. Архив и резервная копия

`Ещё` → `Архив всех выездов`.

Архив читает ту же серверную базу, что и график. JSON/CSV — экспорт для резервного контроля, а не источник текущих данных.

## 10. Восстановление

Импорт JSON сознательно заменяет общую базу после подтверждения. Использовать только из проверенного резервного файла.

## 11. Архитектура production

- `index.html` — единственная структура интерфейса.
- `app.js` — единственная рабочая логика интерфейса, Firebase Auth, Firestore, realtime, архив и экспорт.
- `firebase-config.js` — единственная конфигурация Firebase.
- `firestore.rules` — правила доступа.
- `styles.css` + `final.css` — интерфейс.
- `firebase.json` — hosting/firestore deployment.

Старые `app-v*`, sync bridge, Supabase и альтернативные secure-app версии не подключаются production-страницей.

## 12. Перед следующим изменением

Не создавать новую версию `app-v5`, `app-v6` и т.п. Менять текущий `app.js`, тестировать и фиксировать результат в той же production-ветке.
