# МОНТАЖИ АА — рабочая инструкция

## 1. Источник правды

Общая рабочая база: Cloud Firestore `appData/shared`.

Заметки: Cloud Firestore `appData/notes`.

Рабочие данные не хранятся в localStorage/sessionStorage и не работают по local-first схеме. При отсутствии сети старые данные скрываются, запись блокируется.

## 2. Два телефона

Рабочие устройства подключаются прозрачно через Firebase Anonymous Authentication и используют одни документы Firestore.

Realtime: `onSnapshot`.

Конкурентная запись: Firestore `runTransaction`.

Для публичного масштабирования anonymous access должен быть усилен App Check/ролями или заменён контролируемой аутентификацией.

## 3. Выезды

Основные типы:

- Монтаж
- Замер
- Рекламация
- Доставка
- Сервис
- Доп. доход

Монтаж использует стандартные окна 10:00–12:00, 14:00–16:00 и резервный 3-й слот.

**Ёмкость дня — 3 монтажных окна.** Выполненный монтаж продолжает занимать окно в истории этого дня.

Замер имеет отдельное свободное время и не обязан занимать монтажный слот.

## 4. Замер → Монтаж

Замер сохраняется как самостоятельная история.

Кнопка `Перенести в монтаж` переносит клиента, телефон, адрес, источник и комментарий и создаёт отдельную запись монтажа.

Связь хранится через `convertedToJobId` / `convertedFromMeasureId`.

Платный замер хранит стоимость и факт оплаты. Если сумма засчитывается в последующий монтаж, это отражается через `measureCredit`; исходная запись не удаляется.

## 5. Финансы

Доход = выполненные работы.

Расход = независимые рабочие расходы.

Чистыми = доход − расходы.

Долг = выполненная работа с `paid === false`.

Долг не вычитается из дохода.

## 6. История и архив

Удаление рабочего выезда физически не используется. Вместо него запись переводится в `Отменён` и остаётся в базе.

Расход можно отправить в архив через `cancelled: true`.

## 7. UX

Карточка выезда поддерживает:

- Яндекс;
- 2ГИС;
- звонок;
- отправку адреса;
- В пути;
- Выполнено;
- Оплачено для неоплаченного выполненного выезда.

Главная показывает доход, расход, чистыми, фактическую загрузку, важные сигналы, сегодняшние выезды, расходы, ближайшие дни и заметки.

Календарь открывает полноценную историю выбранной даты.

## 8. Security

Firestore сейчас разрешает доступ аутентифицированному Firebase-клиенту; рабочий транспорт — Anonymous Auth.

Это достаточная связка для текущего закрытого прототипа, но не финальный security posture для публичного продукта. Перед внешним доступом требуется App Check/ограниченные роли или контролируемая аутентификация.

## 9. Перед изменением

1. Не менять `appData/shared` структуру без необходимости.
2. Не создавать новую Firebase project.
3. Не создавать новый runtime `app-vN`/`vN.js`.
4. Не добавлять второй источник правды.
5. Проверить текущий production commit.
6. Сделать backup branch при рискованной работе.
7. Выполнить `npm test`.
8. Проверить существующие реальные записи.
9. Проверить Safari и Chrome.
10. Только после этого deploy.

## 10. Rollback

При критическом сбое не удалять данные. Вернуть код на последний известный рабочий commit, проверить Firebase Hosting/Vercel и только потом разбирать проблему.
