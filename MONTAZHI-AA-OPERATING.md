# МОНТАЖИ АА — рабочая инструкция

## 1. Что является источником правды

- **Общая база:** Cloud Firestore `appData/shared`.
- **Локальная копия:** `localStorage` на каждом телефоне.
- **Резервная копия:** Excel/JSON через раздел «Ещё» → «Архив всех выездов».
- **Интерфейс:** PWA «Монтажи АА».

Приложение работает local-first: если интернет пропал, монтажи можно добавлять и редактировать. После восстановления сети изменения синхронизируются.

## 2. Совместная работа

Firebase Authentication использует Anonymous Sign-In. Оба телефона подключаются к одной общей базе. Изменения монтажей, статусов, дат, сумм и расходов появляются на другом устройстве автоматически.

Важно: не очищать данные сайта/браузера на телефоне до создания резервной копии, если устройство работало полностью офлайн и ещё не успело синхронизироваться.

## 3. Как добавлять монтаж

`+` → «Монтаж» → дата → слот → клиент → телефон → адрес → магазин → сумма → комментарий → сохранить.

Ограничение графика: максимум 3 выезда в день.

Слоты:
- 10:00–12:00
- 14:00–16:00
- 3-й слот / резерв

## 4. Выполненный монтаж

Открыть монтаж → поставить статус **Выполнен** → при необходимости указать дату выполнения.

Именно дата выполнения используется для фактического дохода. Поэтому перенос задним числом не теряет деньги: запись остаётся в архиве, а финансовые итоги пересчитываются по дате выполнения.

## 5. Перенос и отмена

**Перенос:** исходная запись не удаляется. Меняется плановая дата/статус, а выполненная работа может иметь отдельную дату выполнения.

**Отмена:** запись остаётся в архиве, но не попадает в фактический доход.

## 6. Дополнительный доход

Кнопка `+ Доход` используется для вскрытия замка, платной услуги и других работ, которые не являются обычным монтажом.

Пример:
- За что: `Вскрытие замка`
- Сумма: `5000 ₽`
- Дата: фактический день получения денег.

## 7. Расходы

Кнопка `− Расход` — для топлива, парковки, такси, платной дороги и прочих расходов дня.

Расходы отображаются отдельно от доходов:
- сегодня;
- неделя Пн–Вс;
- месяц;
- всё время.

Также считается **чистыми = доход − расходы**.

## 8. Деньги

Главный показатель недели начинается заново каждый понедельник.

Ниже сохраняются:
- сумма текущего месяца;
- сумма за всё время.

В разделе «Деньги» доступны периоды День / Неделя / Месяц / Всё и отдельный контроль доходов, расходов и чистого результата.

## 9. Архив

`Ещё` → `Архив всех выездов`.

Архив содержит всю историю, включая прошлые дни и выполненные монтажи. Запись можно открыть и изменить. После изменения финансовые показатели пересчитываются автоматически.

Экспорт:
- **Excel** — рабочая таблица для ручного контроля;
- **JSON** — полный резерв приложения.

Рекомендуется делать Excel-экспорт минимум раз в неделю.

## 10. Если приложение показывает старые данные

1. Проверить строку статуса в `Ещё`.
2. Если написано `Онлайн · синхронизация с напарником включена` — данные подключены к общей базе.
3. Если `Офлайн` — продолжать работу можно, но дождаться сети перед удалением/очисткой данных браузера.
4. Если после восстановления сети данные не появились, обновить страницу приложения один раз.

## 11. Что нельзя делать

- Не удалять Firestore database.
- Не менять правила Firestore без резервной копии.
- Не очищать данные сайта на обоих телефонах одновременно.
- Не удалять монтаж вместо отмены — отменённые записи нужны для истории.

## 12. Архитектура для будущих исправлений

Главные файлы:

- `index.html` — структура приложения и порядок модулей;
- `app-v4.js` — основной интерфейс и бизнес-логика;
- `archive.js` — архив, редактирование истории и экспорт;
- `firebase-config.js` — подключение Firebase проекта;
- `firebase-sync.js` — совместная синхронизация;
- `pro-features.js` — финансовые и UX-дополнения;
- `styles.css` — визуальная система;
- `firestore.rules` — безопасность базы;
- `firebase.json` — Firebase deployment configuration.

Перед любым изменением сначала проверить зависимость файла от `montaji-aa-data-v4`, не менять структуру данных без миграции и обязательно проверять сценарии: добавление, редактирование, выполнение, перенос, отмена, доход, расход, архив и синхронизация двух устройств.
